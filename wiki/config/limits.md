# 容量与限制

CloudVault 本身很轻，但它仍然受 Cloudflare Workers 和 R2 的额度约束。下面分“应用层限制”和“平台层限制”两部分。

## 应用层限制

这些是代码里明确写死的值：

| 项目 | 限制 | 说明 |
| --- | --- | --- |
| 单次 ZIP 文件数 | 200 | 超过返回 413 |
| 单次 ZIP 总大小 | 512 MB | 按解压前大小计算 |
| 文件夹分享链接有效期 | 最长 3650 天 | `0` 表示永不 |
| 单文件分享有效期 | 最长 3650 天 | 同上 |
| 密码最小长度 | 8 个字符 | 账号和分享密码使用同一策略 |
| 密码最大长度 | 200 个字符 | API 层 |
| 用户名 | 3–32 个字符 | 字母、数字、点、短横线、下划线 |
| 登录会话 | 7 天 | HttpOnly Cookie + KV TTL |
| 分享密码 Cookie | 1 小时 | 只对对应分享路径生效 |
| WebDAV 递归 PROPFIND | 5000 个条目 | 超过返回 `propfind-finite-depth` |
| 小文件直传阈值 | 10 MB | 前端行为 |
| 分片大小 | 16 MB | 前端行为 |
| 同时上传文件数 | 3 | 前端行为 |
| 单文件分片并发 | 3 | 前端行为 |
| 登录失败限流 | 5 次 / 10 分钟 / IP | KV 最终一致，属于节流不是硬保证 |
| WebDAV 失败认证 | 20 次 / 10 分钟 / IP | 同上 |
| 分享密码错误 | 8 次 / 10 分钟 / token + IP | 同上 |

> 这些是代码层限制，不是 Cloudflare 套餐额度。实际能传多大的文件，还取决于 Worker 请求体、CPU 时间、R2 操作和你的套餐。

## 平台层限制

CloudVault 依赖：

- **Workers**：请求体大小、CPU 时间、子请求数、每日请求数；
- **R2**：存储容量、Class A / Class B 操作数、出口流量；
- **KV**：读写次数、存储容量、最终一致性延迟。

Cloudflare 的套餐和价格会变，具体额度以控制台和官方页面为准：

- [Cloudflare Workers 计划](https://workers.cloudflare.com/plans)
- [Cloudflare R2 定价](https://developers.cloudflare.com/r2/pricing/)
- [Cloudflare KV 限制](https://developers.cloudflare.com/kv/platform/limits/)

不要在文档或宣传里承诺“无限存储”或“无限流量”。CloudVault 是自部署工具，账单和额度属于你的 Cloudflare 账号。

## 没有的东西

CloudVault 当前没有：

- 回收站；
- 文件版本历史；
- 文件去重；
- 服务端转码；
- 分片续传；
- 按用户配额；
- 多租户隔离。

删除就是永久删除。需要版本或回收站，应该在 R2 侧做对象版本 / 备份，或使用支持版本控制的存储方案。

## 估算容量

一个粗略的估算方式：

```text
R2 月成本 ≈ 存储 GB × 单价
            + Class A 操作 × 单价
            + Class B 操作 × 单价
```

CloudVault 的读写模式：

- 列目录：R2 `list()`，按页；
- 打开文件：`head()` + 一次范围读取；
- 上传：一次 `put()` 或分片；
- 重命名 / 移动：复制字节再删除源，会产生额外的 Class A/B 操作；
- 统计：定期扫描对象元数据，30 秒缓存。

大目录、频繁重命名和大文件复制，会比“只读分享”更消耗操作额度。

## 什么时候该换方案

如果你的需求是：

- 多人在线协作编辑；
- 数 TB 文件、频繁版本历史；
- 精细的用户配额和审计；
- 完整的多租户 SaaS；

CloudVault 不是最合适的工具。它适合“自己的文件、少量成员、可控分享、低运维成本”的场景。
