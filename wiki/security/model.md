# 安全模型

CloudVault 的安全边界不是“每个用户一个加密空间”，而是“一个受控的私有文件库 + 明确的公开出口”。理解这一点，比记住某个响应头更重要。

## 信任边界

```text
Internet
  │
  ├─ /s/<token>          公开分享：token 即凭据
  ├─ /<folder>/<file>    公开目录：仅限访客共享目录
  ├─ /                  访客页：受设置和共享标记控制
  │
  └─ /admin /api/* /dav/*  需要账号
        │
        ├─ Cloudflare Worker（鉴权、限流、路径校验）
        ├─ R2（文件字节，桶不公开）
        └─ KV（账号、会话、分享、设置）
```

- **R2 桶默认私有**。文件只能通过 Worker 读取；不要开启 R2 公共访问。
- **KV 是控制面**。账号、会话、分享记录、设置都在这里。
- **Worker 是无状态入口**。每次请求重新校验会话和权限。
- **没有数据库**。不存在一个可以被 SQL 注入的查询层。

## 账号与会话

- 密码算法：PBKDF2-SHA256；
- 迭代次数：60,000；
- 派生长度：256 bit；
- 盐：16 字节随机；
- 密码最少 8 个字符；
- 会话有效期：7 天；
- Cookie：`HttpOnly`、`Secure`、`SameSite=Lax`，名为 `session`；
- 会话记录存在 KV，退出登录删除当前会话。

密码哈希参数写在代码里，升级迭代次数需要重新哈希已有账号，属于破坏性变更。当前没有“密码强度计分”或“ breached password 检查”。

## 授权

| 入口 | 需要什么 |
| --- | --- |
| `/admin` | 有效会话 |
| `/api/files` 等 | 有效会话 |
| `/api/settings` / `/api/users` | 有效会话 + `admin` |
| `/dav/*` | HTTP Basic 账号密码 |
| `/s/<token>` | 有效且未过期 / 未撤销的分享 token；有密码时再加 Cookie |
| `/` 访客页 | 无需登录，但只显示明确共享的内容 |

所有账号共享文件库。`user` 角色可以读写全部文件，这是产品设计，不是漏洞；它意味着**不要给不信任的人 `user` 角色**。

## 分享的安全属性

- token：18 字节随机，base64url；
- 单文件一个 token，创建时复用；
- 文件夹链接一个文件夹一个 token；
- 有效期最长 3650 天，`0` 为永不；
- 分享密码使用 PBKDF2 记录；
- 密码通过后写入 HMAC 签名的 Cookie，1 小时有效，`Path` 限定在 `/s/<token>`；
- 密码错误按 token + IP 限流；
- 撤销即删除 KV 记录；
- 文件重命名 / 移动会重定向 token，不会让旧链接指向别的文件。

**分享链接是 bearer token。** 任何拿到链接的人都能访问（除非有密码）。它不会被搜索引擎索引，但可能被聊天记录、截图、日志泄露。不要把它当成“只有收件人能打开”的加密链接。

## 文件路径安全

- R2 key 就是文件 ID，不接受客户端传入任意 key 直接读根目录；
- 路径段拒绝 `.`、`..`、反斜杠、控制字符；
- 每段最长 255 字符，key 最多 64 段；
- 公开简洁地址会校验“文件位于访客共享目录”；
- 文件夹排除标记对列表、下载、预览、分享链接统一生效。

## 响应头

| 头 | 值 |
| --- | --- |
| `X-Frame-Options` | `DENY` |
| `Content-Security-Policy` | `frame-ancestors 'none'`，同源脚本 / 样式 |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | 同源策略 |
| 预览响应 | `default-src 'none'; style-src 'unsafe-inline'; sandbox` |

页面本身使用同源 CSP，含 `unsafe-inline` / `unsafe-eval`，这是当前前端架构的妥协；它不允许把第三方脚本注入页面。预览内容和页面是分开的响应，预览不能执行脚本。

## 限流

| 入口 | 阈值 |
| --- | --- |
| 登录 | 5 次失败 / 10 分钟 / IP |
| 初始化 | 5 次 / 10 分钟 / IP |
| WebDAV 认证 | 20 次失败 / 10 分钟 / IP |
| 分享密码 | 8 次失败 / 10 分钟 / token + IP |

限流计数在 KV，KV 是最终一致的。因此：

- 它是**节流**，不是密码学保证；
- 多边缘节点、并发请求可能让实际次数略高于阈值；
- 不能替代强密码、Cloudflare WAF 或 Access。

## 已知限制

- 没有 2FA / Passkey；
- 没有审计日志；
- 没有病毒扫描；
- 没有服务端静态加密（依赖 Cloudflare 的传输和存储加密）；
- 没有按用户配额；
- 没有回收站和版本历史；
- WebDAV 是 Class 1，没有文件锁；
- 分享密码 Cookie 有效 1 小时，期间同一浏览器不再要求密码；
- 管理员可以重置任何成员密码，这是设计能力，也是高权限风险。

如果你的威胁模型包含“托管方不可信”，CloudVault 不适合存敏感明文；需要在上传前自行加密。
