# 首次初始化

部署完成后，第一次打开站点会被送到 `/setup`。这个页面只做一件事：创建第一个管理员账号，并让这个管理员自动登录。

## 账号规则

| 项目 | 规则 |
| --- | --- |
| 用户名 | 3–32 个字符；只能包含字母、数字、点、短横线和下划线；必须以字母或数字开头和结尾 |
| 密码 | 至少 8 个字符，最多 200 个字符 |
| 角色 | 第一个账号固定为 `admin` |

用户名不区分大小写用于登录查找，但会保留你输入的显示形式。比如 `Alice` 和 `alice` 不能同时存在。

## 操作步骤

1. 打开：

```text
https://<your-host>/setup
```

2. 输入用户名、密码，重复一次密码。
3. 点击 **创建账号**。
4. 成功后会自动登录并进入 `/admin`。

从这一刻开始，`/setup` 会跳转到 `/login`，不会再允许创建第二个“首个管理员”。

## 为什么没有部署密码

旧版 CloudVault 使用一个共享的 `ADMIN_PASSWORD`，没有用户名、不能按人轮换，也无法审计。现在账号存在 KV 里，由应用管理：

- 第一个管理员由 `/setup` 创建；
- 后续成员由管理员在 **用户** 页面添加；
- 每个账号有自己的密码和角色；
- 管理员重置密码后，对方的下一次登录会要求改密码。

如果你是从旧版本升级，且部署里仍然有 `ADMIN_PASSWORD`，CloudVault 会在第一次访问时把它迁移成名为 `root` 的管理员，并标记“必须改密码”。这是兼容路径，不是新部署的推荐做法。

## 初始化之后

1. 进入 **设置**，改站点名称、图标地址。
2. 决定是否开启 **启用访客页面**。关闭时，未登录访问 `/` 会被送到 `/login`。
3. 在 **用户** 中添加成员；普通成员只能管理文件、分享和 WebDAV。
4. 如果站点对公网开放，按 [安全加固](/security/hardening) 做一遍检查。

## 忘记管理员密码怎么办

CloudVault 没有“公开的找回密码”入口，这是故意的：任何能重置管理员的人都应该已经拥有 Cloudflare 账号或 KV 的访问权。

可选路径：

- 还有其他管理员：让另一个管理员在 **用户** 里重置密码；
- 只有最后一个管理员且密码丢失：从 KV 备份恢复，或在 Cloudflare 控制台用 Wrangler 操作 KV；
- 不确定怎么操作：先看 [故障排查](/help/troubleshooting)，不要直接删 KV 命名空间，否则账号、分享和设置都会丢。

## 初始化失败

| 提示 | 原因 |
| --- | --- |
| `This vault is already initialized` | KV 里已有账号，去 `/login` |
| `Username must be 3-32 characters` | 用户名长度不对 |
| `Username may only contain letters, digits, dot, dash and underscore` | 用户名有不允许的字符 |
| `Password must be at least 8 characters` | 密码太短 |
| `Passwords do not match` | 两次输入不一致 |
| `Too many attempts` | 当前 IP 触发了初始化限流，等窗口结束再试 |

初始化接口本身也有限流，正常操作不会触发；连续失败才会。
