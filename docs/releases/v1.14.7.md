# CloudVault v1.14.7

**Build your own cloud.**

CloudVault is a serverless personal file-sharing layer on Cloudflare Workers + R2. No VPS, no database, and no separate object-storage service.

## What changed

- Added a short feature caption below every README screenshot: file management, public guest page, sharing settings, and single-file share page.
- Updated the Chinese and English READMEs with matching captions and refreshed public/share screenshots.
- Replaced the visitor-facing attribution footer on 404, guest, login, and share pages with `Build your own · zqs1qiwan/CloudVault`.
- Refreshed the public guest and single-file share screenshots so the new footer is visible in the README.
- Kept all README badges as repository-local static SVGs, with the release badge updated to `v1.14.7`. Badges do not depend on shields.io availability.
- Added issue templates, a security policy, and contribution guidelines for a clearer first-contribution path.

## Deploy

One-click deploy:

https://deploy.workers.cloudflare.com/?url=https://github.com/zqs1qiwan/cloudvault

After deployment, open `/setup` and create the first administrator account.

Manual deployment instructions are in the [README](https://github.com/zqs1qiwan/cloudvault#部署).

## Upgrade notes

No breaking changes. Existing Workers, R2 buckets, KV namespaces, accounts, and share links continue to work. There is no database migration in this release.

## Scope and limits

CloudVault is intentionally a small, single-tenant file tool. It does not provide collaborative document editing or a hosted SaaS. Workers and R2 quotas, request limits, and Cloudflare billing still apply.
